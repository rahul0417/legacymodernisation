# Dual-run parity harness — shorty

Runs the legacy PHP shorty app and the new FastAPI port side-by-side **inside a private
docker network** (127.0.0.1-bound, no published ports), with identical seed data, then
diffs their responses.

## Status

🟡 **PARTIAL.** The PHP side (this directory's Dockerfile + overlay + seed) is ready.
The FastAPI side and the parity runner script are added after Stage 4 CodeGen produces
the FastAPI app at `../generated/backend/`.

## Security posture

Per the engagement security policy:
- **No published ports.** All services accessible only via the docker network (or
  `docker exec` from the host).
- **No host filesystem mounts** beyond:
  - `../source/` → mounted read-only at `/var/www/html` (read-only PHP source)
  - `php-overlay/` → mounted read-only at `/var/www/html` (overlay)
- **Ephemeral DB volumes.** MySQL and PostgreSQL data live in named docker volumes that
  are destroyed on `docker compose down -v`. No persistence outside the harness run.
- **Hard-coded development passwords** (`shorty_dev_only`). Never reused outside this harness.

## How to run (once complete)

```bash
cd migrations/shorty/dual-run
docker compose up -d                                          # spins up all 4 services
docker compose run --rm parity-runner \
    python parity-runner.py \
    --fixtures fixtures/inputs.jsonl \
    --report parity-report.json
jq '.green_path_match' parity-report.json                     # expect 1.0
docker compose down -v                                        # tear down + wipe volumes
```
